# 프로필 화면

- 메인 헤더의 사람 아이콘 → `/#profile`.
- 로그인 사용자는 `GET /api/v1/auth/me`의 `data.displayName`, `data.profileImageUrl`로 소셜 이름과 프로필 사진을 표시합니다. 표시 이름이 비어 있으면 `YU FESTA`, 사진이 없거나 로딩에 실패하면 기본 프로필 이미지를 표시합니다.
- 인스타팅 신청이 없어도 소셜 프로필을 표시합니다. 신청 내역 조회가 지연되거나 실패해도 소셜 프로필은 갱신됩니다.
- 인스타그램 아이디와 인스타팅 참여 내역은 본인 신청 조회에서 가져옵니다. 신청 닉네임은 소셜 표시 이름과 별도로 참여 내역에 보존합니다.
- `마이페이지` 상단에 작은 소셜 프로필을 표시하고, 아래에 `인스타팅 신청 내역`, `설정`을 배치합니다.
- 신청 전에는 푸르마와 신청 버튼을, 신청 후에는 회차 카드 안에 마감·발표 시각과 접히는 신청 정보를 표시합니다. 수정·취소 버튼은 해당 신청을 변경할 수 있을 때만 표시합니다. 접수 전·마감 등 변경 불가 상태에서는 비활성 버튼을 노출하지 않으며, 요청 처리 중에는 중복 실행을 막기 위해 버튼을 비활성화합니다.
- 신청 정보에는 인스타 아이디·닉네임·성별·나이대·관심 태그·선호 공연·입력한 소개를 표시합니다. `needsSlotReselect=true`이면 공연 재선택 안내를 표시합니다.
- `CARRIED` 신청만 `자동 신청됨`으로 안내합니다. 매칭된 사용자의 다음 회차 신청은 결과 API의 `canRejoin`, `hasNextRoundApplication`, `nextRoundSeq`를 확인한 뒤 재참여 API로 연결합니다. 첫 신청과 미매칭 후 취소한 사용자의 재신청은 신청 양식으로 연결합니다.
- 회차 순서로 카드를 배치하고 가장 최근의 매칭 성공 카드만 파란색으로 강조합니다. 이전 결과는 흰색 카드의 `결과 다시 보기`로 연결합니다. 미매칭 사유는 API에 없으므로 특정 원인을 단정하지 않습니다.
- 남은 시간과 수정·취소 마감은 `match/summary.serverNow` 및 응답 수신 후 경과 시간으로 판단합니다. 예정 발표 시각이 지나도 서버가 발표하지 않았다면 결과를 임의로 공개하지 않습니다.
- `공지 알림` 스위치는 실제 기기의 구독 상태를 조회합니다. 등록·해제에 성공했을 때만 표시를 변경하고, 실패하면 기존 상태와 오류 안내를 유지합니다. 로그인만으로 알림을 켜지 않습니다.
- 비로그인 사용자는 로그인 화면으로 이동합니다. 개발 중 `.env.local`에 `VITE_PROFILE_PREVIEW=true`를 설정하면 예시 프로필을 볼 수 있으며 기본값은 비활성화입니다.
- 예시 프로필은 실제 로그인 세션이 아니며 화면에 미리보기임을 표시합니다. 로그인 사용자가 있으면 예시 데이터보다 우선합니다.
- 분기 검증: `npm run test:api`. `profile-history.test.ts`에서 회차 정렬·강조·자동 이월·서버 시각·이전 결과 경로·오류 처리를 확인합니다.

## 현재 API 범위와 백엔드 추가 요청

2026-09-29 [공개 Swagger](https://api.yufesta.com/swagger-ui/index.html?urls.primaryName=public#/Match/getMyApplication)의 실제 스키마를 확인했습니다.

- `GET /api/v1/match/applications/me`는 Swagger 설명상 **현재 회차**의 신청을 반환하며, 회차 선택 파라미터가 없습니다. 응답은 신청 한 건이고, 프론트는 반환된 `roundSeq`와 같은 회차에만 상세를 연결합니다. 사용자가 제공한 2회차 실제 응답도 `roundSeq: 2`입니다. 이전 회차와 내용이 같더라도 1회차 신청 원본 조회로 판단하지 않습니다. 응답이 없는 다른 회차에는 신청 내용을 복사하지 않고 상세 펼치기를 생략합니다.
- `GET /api/v1/match/results/me?roundSeq=N`으로 본인이 참여한 이전 결과를 확인할 수 있습니다. 최근 발표 회차까지 조회하되 `APPLICATION_NOT_FOUND`인 회차만 제외합니다. 이전 결과 주소로 직접 재진입해도 서버가 본인 참여·공개 여부를 검사합니다.
- 요약 API는 현재·다음 회차 시각만 제공합니다. 지난 회차의 `16:00 발표 완료`처럼 정확한 시각은 알 수 없으므로 `발표 완료`로 표시합니다.
- 이미지의 모든 상세를 제공하려면 **내 회차별 신청 이력 API**가 필요합니다. 각 항목에 신청 ID, 회차 번호·상태·발표 시각, 해당 회차에 제출한 신청 정보, 매칭 여부를 포함해 주세요. 또는 기존 신청 조회에 `roundSeq`를 지원하고 결과 응답에 발표 시각을 추가할 수 있습니다. 이는 제안이며 현재 지원되는 경로가 아닙니다.
- 신청 내역이 없는 사용자의 인스타 ID는 현재 API로 알 수 없어 상단에서 생략합니다. 소셜 이름과 프로필 사진은 그대로 표시합니다.
- 운영 정책 확인에 따라 전체 회차 종료 안내와 개인정보 동의 모달에 `축제 종료 7일 뒤 삭제`를 표시합니다. 실제 삭제 실행은 백엔드의 책임이며 프론트 문구만으로 삭제되지 않습니다. 빈 상태의 캐릭터는 프로젝트에 있는 푸르마 이미지를 사용했습니다.

## 브라우저 확인

운영 데이터를 변경하지 않는 모의 API로 신청 전·발표 대기·1차 성공 및 2차 신청·재참여·자동 이월·전체 발표·마감·접수 예정 화면을 확인합니다. 320px와 390px에서 가로 넘침, 신청 정보 펼치기, 수정·취소·재참여, 과거 결과 조회와 재진입, 공지 알림 및 로그아웃을 검사합니다. 실제 기기의 푸시 수신과 운영 계정으로 서버에 저장되는지는 별도 QA 대상입니다.
