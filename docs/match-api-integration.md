# 인스타팅 사용자 API 연결

## 연결한 화면

- 홈: `GET /api/v1/match/summary`로 회차·접수 상태·신청자 수·내 신청 여부를 표시합니다. 서버 시각과 응답 수신 후 경과 시간으로 접수 마감과 시·분·초 카운트다운을 계산합니다.
- 신청: `GET /api/v1/match/tags`의 코드/이름을 사용합니다. 최대 3개 선택 후 `POST /api/v1/match/applications`로 제출하며, 서버 성공 응답을 받은 뒤 완료 화면을 표시합니다.
- 프로필: `GET /api/v1/match/applications/me`로 현재 신청을 표시합니다. 404는 현재 신청 없음으로 처리합니다. 요약 응답에 있는 최근 발표 회차도 결과 목록에 포함합니다. 전체 과거 신청 이력을 제공하는 API는 주어지지 않았습니다.
- 취소: 마감 전 확인 UI에서 `DELETE /api/v1/match/applications/me`를 호출합니다.
- 재참여: 이전 회차 매칭 성공자이며 현재 회차 신청이 없을 때 `POST /api/v1/match/applications/rejoin`을 호출합니다.
- 결과: `GET /api/v1/match/results/me?roundSeq=...`를 호출합니다. 409는 발표 대기, 다른 실패는 재시도 가능한 오류로 처리합니다.
- 신고: 결과 카드의 `matchId`로 `POST /api/v1/match/reports`를 호출하고, 성공 후 해당 카드를 즉시 숨깁니다.

로그인 쿠키와 `X-XSRF-TOKEN`은 기존 공통 API 클라이언트로 전송합니다. 변경 요청을 자동 재시도하지 않습니다. 신청/취소/재참여/신고 후 상태를 다시 읽고, 화면 복귀 및 30초 주기로 요약과 신청 상태를 갱신합니다. 브라우저의 과거 미리보기 신청은 실제 신청 여부에 사용하지 않습니다.

## 인증 API

- `GET /api/v1/auth/me`: 로그인 상태 조회에 사용하며, 401은 비로그인으로 처리합니다. 네트워크 오류는 비로그인과 구분하여 재시도를 안내합니다.
- `GET /api/v1/auth/csrf`: 쓰기 요청 전에 `XSRF-TOKEN` 쿠키가 없으면 발급받습니다. 동시 요청은 발급 요청을 공유하고, 쿠키 값을 `X-XSRF-TOKEN` 헤더로 전송합니다. 발급 실패 또는 쿠키를 읽을 수 없는 경우 쓰기 요청을 보내지 않고 오류를 표시합니다.
- `POST /api/v1/auth/logout`: 프로필의 로그아웃 버튼에서 호출합니다. 204 성공 후 로그인 상태와 개인 신청 정보를 즉시 초기화하고 홈으로 이동합니다. 이전에 시작한 조회 응답이 개인 정보를 다시 표시하지 않도록 무효화합니다. 실패 시 화면에 오류를 표시하며 다시 시도할 수 있습니다.
- 모든 요청은 `credentials: include`를 사용합니다. 프런트엔드에서 CSRF 쿠키를 읽을 수 있도록 서버의 쿠키 도메인·경로 설정이 필요합니다.

## 명세 확인이 필요한 부분

사용자가 미확인 결과 구조를 임의로 정해 우선 구현하도록 요청하여, `src/utils/matchResult.ts`에서 아래 임시 성공 응답을 검증합니다. **실제 백엔드 계약으로 확인된 구조는 아닙니다.** 형식이 다르면 가짜 매칭/미매칭 결과 대신 오류를 표시합니다.

```json
{
  "status": 200,
  "message": "ok",
  "data": {
    "roundSeq": 1,
    "status": "MATCHED",
    "cards": [
      { "matchId": 77, "nickname": "축제친구", "instagramId": "festa_friend" }
    ]
  }
}
```

- 미매칭: `data.status`가 `UNMATCHED`인 경우입니다. 모든 카드를 신고한 경우의 `MATCHED` + 빈 `cards`와 구분합니다. 서버에서 받은 카드 순서를 유지합니다.
- 신고 사유: 캡처에서 확인된 `FAKE`만 사용하며 상세 설명을 입력할 수 있습니다. 나머지 사유와 길이/필수 제약은 추가 명세가 필요합니다.
- 신청 성공 및 재참여·신고 성공 응답: 본문 구조가 없어 응답 데이터를 사용하지 않고 재조회합니다. 204·빈 200·공통 JSON 응답을 지원합니다.
- 내 신청 조회: 기존 저장소의 `MatchApplication` 타입을 유지했습니다. 이번 캡처에는 성공 응답이 없으므로 실서버에서 확인해야 합니다.
- 약관/개인정보 버전: 요청 예시의 `2026-09-01`을 `src/utils/match.ts`에 지정했습니다.
- 기존 ‘보고 싶은 공연’과 ‘여러 명 매칭’ 입력은 요청 스키마에 없어 신청 화면에서 제외했습니다. 요청에 있는 닉네임·인스타 ID·성별·나이대·관심 태그·소개·필수 동의를 사용합니다.

## 검증

- `npm run test:api`: 신청 데이터 변환, 인증·CSRF, 신청/취소/재참여, 오류 처리, 서버 시간, 임시 결과 구조, 프로필 회차를 검사합니다.
- `npm run test:countdown`, `npm run build`, `npm run lint`.
- 로컬 모의 서버에서 브라우저로 신청 → 프로필 갱신 → 발표 대기 → 취소 → 재참여 → 결과 카드 공개 → 신고 후 카드 제거를 확인했습니다.
- API 기본 주소와 로컬 환경은 `https://api.yufesta.com`으로 설정했습니다. `VITE_API_BASE_URL`로 다른 환경을 지정할 수 있습니다.
- 2026-09-24 사용자 브라우저 캡처에서 localhost Origin에 대한 CORS 허용과 공개 요약 조회 200을 확인했습니다. 같은 환경의 로그인 상태 조회는 401이었습니다.
- 소셜 로그인 리다이렉트가 운영 도메인으로 설정되어 있으므로 인증이 필요한 기능은 운영 환경에서 최종 확인해야 합니다. 로그인·로그아웃·신청·결과·신고의 실서버 검증과 실제 결과 JSON 확인은 남아 있습니다. 테스트용 모의 서버는 제품 코드에 포함하지 않았습니다.
