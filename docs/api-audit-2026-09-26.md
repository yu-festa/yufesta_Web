## 이번 작업의 사용자 동작

- 운영자 → 공연 동아리 → 대표 사진: JPEG·PNG 선택, 10MB 이하 검사, 미리보기, 저장·교체, 삭제 확인. 저장 요청 중 중복 전송을 막고 실패 시 선택 파일을 유지합니다.
- 새 동아리 정보 저장 후 사진 편집 화면으로 연결합니다. 정보 저장과 사진 업로드를 분리하여 업로드 재시도로 동아리가 중복 등록되지 않도록 합니다.
- 사진은 multipart의 file 필드로 보내고 공통 CSRF·인증 쿠키를 사용합니다. Content-Type의 boundary는 브라우저가 생성합니다. 성공 응답 스키마가 생략된 업로드는 응답 필드에 의존하지 않고 목록을 다시 읽습니다.
- 메인 라인업·공연 상세는 기존 public clubs의 photoUrl을 그대로 사용하므로 다시 조회하면 업로드·삭제 결과가 표시됩니다.
- 축제 지도와 운영자 장소 폼을 공연장·화장실·배달존으로 통일합니다. 예전 부스·편의·안내 항목은 제거합니다.
- 배달존이 등록돼 있으면 핀·목록·상세·이벤트를 표시합니다. 빈 목록일 때만 미등록 안내를 보여줍니다.
- 지도 하단 장소 목록은 현재 위치가 있으면 직선 거리순, 없으면 서버 순서로 표시합니다. 목록 선택으로도 상세를 열 수 있으며 실패한 상세는 재조회할 수 있습니다.
- 기존 타임테이블·공연 상세·분실물 게시판 디자인은 유지합니다.

## 권한 및 현재 API 범위

- 비로그인 auth/me의 401은 로그인되지 않은 상태로 처리합니다. 응원 목록·작성은 비로그인 사용이 가능합니다.
- 인스타팅·분실물 작성/해결/삭제·콘텐츠 신고는 로그인 필요, 운영자 화면은 STAFF 또는 OWNER 필요. 회차 발표는 OWNER 전용입니다. 서버가 최종 권한을 검사합니다.
- 모든 POST/PATCH/PUT/DELETE는 기존 공통 클라이언트에서 쿠키와 X-XSRF-TOKEN을 전송합니다. 쓰기 요청을 자동 재시도하지 않습니다.
- 관리자용 비공개 장소 목록·상세 API는 없습니다. 공개 장소 조회 및 현재 화면에서 저장한 장소 관리 범위를 유지했습니다.
- 숨긴 응원·분실물 전체 조회 API도 없습니다. 기존 신고 목록 또는 대상 ID로 복구합니다.
- 분실물 사진·댓글·개별 상세 조회·소유자 구분 필드는 아직 없습니다. 기존처럼 최근 목록에서 상세를 열며 사진·댓글 UI는 숨깁니다. 해결·삭제 권한은 서버에서 확인합니다.
- auth/me는 role만 제공하므로 소셜 계정 이름·이메일·프로필 사진은 가져오지 않습니다.
- 전체 과거 매칭 이력, 최신 동의 문서/버전, 알림 수신함 API는 없습니다. 현재 신청·최근 결과, 기존 동의 버전, 공지 목록 연결을 유지합니다.
