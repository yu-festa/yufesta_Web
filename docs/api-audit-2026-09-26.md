# Swagger API 연동 점검 — 2026-09-26

- 기준 문서: [public](https://api.yufesta.com/v3/api-docs/public), [admin](https://api.yufesta.com/v3/api-docs/admin)
- 분실물 확장 재점검 기준 public 33개, admin 37개: 총 70개 메서드·경로를 API 모듈 및 화면 호출부와 대조했습니다.
- 앞선 점검에서 동아리 대표 사진 업로드·삭제와 장소 분류 변경을 반영했습니다. 이후 문서와 비교하여 분실물 public 6개·admin 1개 신규 작업을 추가 연결했습니다.
- 최신 변경 계약: `LostItemResponse.image`와 댓글/답글 스키마 추가, 콘텐츠 신고 대상에 `LOST_ITEM_COMMENT` 추가. 이외 API 경로·작업·스키마 변경은 없었습니다. 오픈 알림 구독·예약 발송 API는 아직 없습니다.

## 분실물 확장 재점검

- 기존 게시판 디자인을 유지하고 목록 썸네일, 상세 사진, 선택·미리보기·삭제 UI를 연결했습니다. JPEG·PNG, 10MB 이하, 글당 한 장을 허용합니다.
- 글 저장 후 사진 업로드만 실패하면 글 ID를 유지하고 사진만 재시도하거나 사진 없이 완료합니다.
- 비로그인 댓글 조회, 로그인 댓글·답글 등록/본인 삭제/신고를 연결했습니다. 댓글·답글은 최대 200자이며 답글의 답글은 제공하지 않습니다.
- `mine`으로 본인 댓글 삭제, `postAuthor`로 작성자 배지를 표시합니다. 삭제된 댓글 원문을 숨기고 답글은 유지합니다.
- 운영자 신고 대상에 분실물 댓글을 추가하고 댓글·답글 숨김/복구를 연결했습니다. 신고의 원글 번호가 없어 글 번호 직접 입력을 사용하며, 공개 글 목록에서 진입하면 글 번호가 자동 입력됩니다.
- 분실물 업로드 작업에 성공 상태 설명은 생략돼 있지만 연결된 응답 스키마는 `ApiResponseLostItemImageResponse`입니다. 기존 공통 응답 래퍼를 해제하여 사진 ID·원본·썸네일 URL을 사용합니다.

## 이번 작업의 사용자 동작

- 운영자 → 공연 동아리 → 대표 사진: JPEG·PNG 선택, 10MB 이하 검사, 미리보기, 저장·교체, 삭제 확인. 저장 요청 중 중복 전송을 막고 실패 시 선택 파일을 유지합니다.
- 새 동아리 정보 저장 후 사진 편집 화면으로 연결합니다. 정보 저장과 사진 업로드를 분리하여 업로드 재시도로 동아리가 중복 등록되지 않도록 합니다.
- 사진은 multipart의 file 필드로 보내고 공통 CSRF·인증 쿠키를 사용합니다. Content-Type의 boundary는 브라우저가 생성합니다. 성공 응답 스키마가 생략된 업로드는 응답 필드에 의존하지 않고 목록을 다시 읽습니다.
- 메인 라인업·공연 상세는 기존 public clubs의 photoUrl을 그대로 사용하므로 다시 조회하면 업로드·삭제 결과가 표시됩니다.
- 축제 지도와 운영자 장소 폼을 공연장·화장실·배달존으로 통일합니다. 예전 부스·편의·안내 항목은 제거합니다.
- 배달존이 등록돼 있으면 핀·목록·상세·이벤트를 표시합니다. 빈 목록일 때만 미등록 안내를 보여줍니다.
- 지도 하단 장소 목록은 현재 위치가 있으면 직선 거리순, 없으면 서버 순서로 표시합니다. 목록 선택으로도 상세를 열 수 있으며 실패한 상세는 재조회할 수 있습니다.
- 기존 타임테이블·공연 상세·분실물 게시판 디자인은 유지합니다.

## 권한 및 현재 API 범위

- 비로그인 auth/me의 401은 로그인되지 않은 상태로 처리합니다. 응원 목록·작성은 비로그인 사용이 가능합니다.
- 인스타팅·분실물 작성/해결/삭제·콘텐츠 신고는 로그인 필요, 운영자 화면은 STAFF 또는 OWNER 필요. 회차 발표는 OWNER 전용입니다. 서버가 최종 권한을 검사합니다.
- 모든 POST/PATCH/PUT/DELETE는 기존 공통 클라이언트에서 쿠키와 X-XSRF-TOKEN을 전송합니다. 쓰기 요청을 자동 재시도하지 않습니다.
- 관리자용 비공개 장소 목록·상세 API는 없습니다. 공개 장소 조회 및 현재 화면에서 저장한 장소 관리 범위를 유지했습니다.
- 숨긴 응원·분실물 전체 조회 API도 없습니다. 기존 신고 목록 또는 대상 ID로 복구합니다.
- 분실물 개별 상세 조회·글 소유자 구분 필드는 아직 없습니다. 최근 목록에서 상세를 열고 사진 관리·해결·삭제 권한은 서버가 확인합니다. 댓글에는 별도 `mine` 값이 있어 본인 댓글에만 삭제를 표시합니다.
- 운영자 댓글 신고 목록에는 `lostItemId`가 없습니다. 현재 API 범위에서 원글 번호를 직접 입력해 숨김/복구하도록 연결했습니다.
- auth/me는 role만 제공하므로 소셜 계정 이름·이메일·프로필 사진은 가져오지 않습니다.
- 전체 과거 매칭 이력, 최신 동의 문서/버전, 알림 수신함 API는 없습니다. 현재 신청·최근 결과, 기존 동의 버전, 공지 목록 연결을 유지합니다.

## 검증

- 앞선 점검: test:admin 11개, test:api 31개, test:map 15개, test:lost 4개: 총 61개 통과.
- 분실물 확장 후: test:lost 10개, test:admin 11개 통과. 업로드 multipart·CSRF·입력 제한·댓글/답글·신고·운영자 공개 상태·실패 전파를 검사했습니다.
- 로컬 모의 API의 실제 화면에서 사진 업로드 실패 후 재시도(글 중복 없음), 댓글·답글 작성/삭제/신고, 비로그인 조회, 운영자 댓글 숨김/복구를 확인했습니다. 모바일 390px에서 사진·댓글 배치와 가로 넘침 없음을 확인했습니다.
- 프로덕션 빌드와 린트 검사 통과.
- 로컬 모의 API를 사용하는 브라우저에서 사진 선택·미리보기·저장·삭제 확인창·삭제 후 빈 사진 상태를 확인했습니다. 모바일 폭에서도 사진 관리 UI를 확인했습니다.
- 모의 장소로 배달존 필터 → 목록 → 위치·이벤트 상세 표시를 확인했습니다. 검증 주소 127.0.0.1:5186에서는 카카오 SDK 로딩이 실패하여 실제 지도 바탕·핀 렌더링은 이번 브라우저 검증 범위에 포함하지 않았습니다.
- 운영 서버의 공개 clubs·places 조회로 사진 URL이 절대 주소이고 장소 분류가 최신 계약에 맞는 것을 확인했습니다.
- 실제 운영 서버에 업로드·삭제·신청·발표 등 쓰기 요청은 보내지 않았습니다. 실제 로그인 계정·운영 저장소를 포함한 최종 확인은 배포 후 필요합니다.
