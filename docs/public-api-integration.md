# 공개 API 연결 내역

기준: 2026-09-24 운영 서버의 public OpenAPI 문서(/v3/api-docs/public). 총 27개 작업을 화면 또는 공통 요청 처리에 연결했습니다. Swagger의 public은 문서 그룹 이름이며, 모든 API가 비로그인용이라는 뜻은 아닙니다.

## 이번에 추가·수정한 내용

### 신청·수정

- 수정 주소는 /main#instating-edit. 서버에서 읽은 현재 신청의 닉네임·인스타 ID·성별·나이대·태그·소개를 채웁니다. 임시 브라우저 신청 데이터를 가져오지 않습니다.
- 닉네임 2~8자, 인스타그램 ID 형식, 성별, 소개 최대 40자, 중복 없는 태그 최대 3개를 검사합니다. 나이대·태그·소개는 선택 사항으로 비울 수 있습니다.
- 신규 신청은 개인정보·이용약관·만 19세 이상 확인 후 POST합니다. 수정은 PATCH 스키마에 맞춰 동의 버전을 다시 보내지 않습니다.
- 선호 공연은 `GET /match/slots`의 현재 회차 선택지에서 고르고 `wantedSlotId`로 보냅니다. 프로필은 `wantedSlot`을 표시하고 `needsSlotReselect`가 true면 재선택을 안내합니다.
- 접수 중이고 서버 시각 기준 마감 전일 때 신청·수정·취소가 가능합니다. 최종 허용 여부는 서버 응답으로 결정됩니다.
- 저장·취소·재참여 성공 후 요약과 내 신청을 다시 읽습니다. 처리 중 버튼 중복 클릭을 막고 실패를 성공 화면으로 표시하지 않습니다.

### 매칭 결과·신고·재참여

- 기존 임시 cards 필드를 제거하고 실제 partners 배열을 사용합니다.
- 카드에 nickname, instagramId, ageBand, intro, tags를 표시하며 commonTags는 하트와 색상으로 강조합니다. 서버 카드 순서를 유지합니다.
- 카드의 `wantedSlot`과 `sameSlot`으로 상대의 선호 공연 및 같은 공연 여부를 표시합니다.
- nextRoundSeq, hasNextRoundApplication, canRejoin을 사용해 마지막 회차/다음 회차 신청 완료/재참여 가능 상태를 표시합니다. 재참여 가능 여부를 임의로 계산하지 않습니다.
- UNMATCHED와 신고 후 MATCHED + 빈 partners를 구분합니다. 전자는 미매칭 결과, 후자는 표시할 카드 없음입니다.
- 결과 조회의 409는 발표 대기, 다른 실패는 오류 및 재조회 버튼으로 처리합니다.
- 신고 사유 PROFILE(불쾌한 프로필), FAKE(허위 정보·성별 위조), OTHER(기타)를 선택할 수 있습니다. 상세는 선택 사항이며 최대 500자입니다.
- 모든 상태 변경은 해당 버튼을 누를 때만 전송하며 자동으로 재실행하지 않습니다.

### 응원글

- 임시 응원 배열과 브라우저 안에서만 추가되던 동작을 실제 GET/POST로 바꿨습니다.
- 1~40자 등록, 서버가 정한 ID·작성자 표시명·작성 시각을 사용합니다. 처음 작성 시 서버가 익명 식별 쿠키를 발급하는 방식입니다. 목록에는 별도의 '내 응원' 표시를 하지 않습니다.
- 등록 실패 시 입력을 유지합니다. 성공한 응원만 목록에 추가하고 같은 ID가 목록에 이미 있으면 중복 추가하지 않습니다.
- 등록 완료 문구는 2초 뒤 사라집니다. 메인 응원 띠는 메시지를 복제해 표시하지 않고, 실제 응원 수에 맞춰 이동 시간을 조정합니다.
- 최신 50개를 조회하며 화면은 10개씩 펼칩니다. 전체 건수나 서버 페이지 이동 기능이 없어 '최근 응원'으로 표시합니다. 로그인 사용자는 응원 신고를 할 수 있습니다.

### 타임테이블·동아리·분실물

- 타임테이블과 이미지 저장은 실제 `/timetable` 응답을 사용하며 변경 시간, 지연, LIVE 상태를 반영합니다. 메인 공연 목록과 상세는 `/clubs`, `/clubs/{id}`를 사용합니다.
- 분실물 목록·등록·해결·삭제는 서버 저장 API로 전환했습니다. 신고는 `/content-reports`로 전송합니다. 사진과 댓글은 서버 API가 없어 UI에서 숨겼습니다.
- 분실물 상세 조회 API가 없어 최근 50건 목록에 있는 글만 상세에서 열 수 있습니다. 소유자 여부를 응답에서 알 수 없으므로 해결·삭제는 서버가 본인 글 여부를 최종 검사합니다.

### 공지

- /main#notices 목록, /main#notices/{id} 상세를 추가했습니다. 기존 화면의 파란색·둥근 카드 디자인을 사용합니다.
- 종 아이콘은 공지 목록을 열고, 메인 배너는 최신 50개 중 banner=true인 첫 공지를 열도록 연결했습니다. 대상 공지가 없으면 목록으로 안내합니다.
- 제목·본문·작성 시각을 표시합니다. 본문은 줄바꿈을 유지한 일반 텍스트로 렌더링하며 HTML을 실행하지 않습니다.
- 로딩, 빈 목록, 삭제된 공지의 404 및 서버 오류를 구분하고 다시 불러오기를 제공합니다.
- 관리자 화면도 같은 공개 공지 API 모듈을 공유합니다.

## 기존 연결 유지 및 운영 확인 사항

- 모든 요청은 credentials: include로 쿠키를 전송합니다. POST/PATCH/DELETE는 XSRF-TOKEN 값을 X-XSRF-TOKEN 헤더에 넣습니다. CSRF 발급 실패나 읽을 수 없는 쿠키는 오류로 표시하고 쓰기를 보내지 않습니다.
- 요약·인증·현재 신청은 관련 화면에서 30초마다 및 창 복귀 시 갱신합니다. 공지·응원은 화면 진입과 창 복귀 시 갱신합니다. 변경 요청은 자동 재시도하지 않습니다.
- 인스타팅 남은 시간은 serverNow와 수신 후 경과 시간을 기준으로 시·분·초만 표시하며 하루 이상은 총 시간으로 환산합니다.
- 지도 API는 이미 연결되어 있습니다. 서버 장소가 없거나 목록 조회에 실패하면 저장된 장소 안내를 표시한다는 문구와 함께 기존 안내를 제공합니다. 지도 SDK의 앱 키·허용 도메인 설정은 별도입니다.
- 약관·개인정보 버전은 기존 설정인 2026-09-01을 유지했습니다. 공개 API에는 최신 동의 문서·버전 조회 API가 없으므로 실제 운영 문서와 버전이 다르면 별도 변경해야 합니다.
- auth/me는 role만 제공하므로 소셜 계정의 이메일·이름·사진은 이 API로 가져올 수 없습니다. 현재 신청 닉네임이 없으면 프로필 이름은 YU FESTA로 표시합니다.
- 프로필에는 현재 신청과 최근 발표 결과만 표시합니다. 전체 과거 신청 이력 API는 없습니다. 응원·공지 역시 최신 최대 50개만 조회할 수 있습니다.
- 푸시 알림 수신함 API는 없습니다. 종 아이콘은 공지 목록입니다.
- 로컬 프론트에서 운영 API를 호출하더라도 소셜 로그인 복귀 주소·인증 쿠키 설정에 따라 인증이 유지되지 않을 수 있습니다. 실제 로그인 계정으로 최종 확인하려면 운영에 배포된 프론트와 API에서 확인해야 합니다.

## 로컬 CSRF 프록시

- 개발 환경에서는 `/api/v1` 요청을 Vite 프록시로 전달합니다. `.env.local`의 `VITE_API_BASE_URL`은 실제 백엔드 주소로 유지하며, 설정 변경 후 개발 서버를 다시 시작합니다.
- 운영 서버가 발급하는 쿠키의 Domain만 제거해 localhost에서 저장하고 읽을 수 있도록 합니다. Secure, HttpOnly, SameSite 속성과 서버의 CSRF 검사는 유지합니다.
- 응원 작성은 로그인 확인 결과와 무관하게 CSRF 쿠키와 헤더를 사용합니다. 비로그인 상태의 auth/me 401은 정상적인 비로그인 응답입니다.
- 배포 빌드는 기존처럼 API 주소로 직접 요청합니다. 개발 프록시를 끄려면 `VITE_DEV_API_PROXY=false`를 설정합니다. 소셜 로그인 URL과 운영 도메인 복귀 설정은 이 프록시로 변경하지 않습니다.

- npm run test:api: 인증·CSRF, 신청/수정/취소/재참여, 실제 결과 계약, 입력 제한, 응원·공지 응답 및 오류, 시각 변환, 개발 프록시, 타임테이블 배치를 포함한 29개 검사.
- npm run test:admin: 기존 관리자 API와 새 운영 콘텐츠 API 검사 8개.
- npm run test:lost: 신규 일정·동아리·분실물·콘텐츠 신고의 공개 계약 및 제목·내용 표시 검사 4개.
- npm run test:launch: 랜딩 전환·최초 스플래시 7개 검사.
- npm run build, npm run lint.
- 개발 프록시를 통한 운영 CSRF 발급의 204 응답과 쿠키 Domain 제거를 확인했습니다. 운영과 같은 쿠키 속성을 사용하는 모의 서버에서 브라우저의 비로그인 응원 등록을 검증했으며, CSRF 누락 요청은 거절되는 것도 검사했습니다.
- 로컬 모의 서버의 UI에서 공지 배너→상세→목록 및 404 오류, 응원 등록 성공·실패와 비로그인 등록, 신청 수정→프로필 갱신→취소, 발표 대기·결과 카드 상세→신고 후 카드 숨김→재참여 및 로그아웃를 확인했습니다. 쓰기 요청의 CSRF 헤더와 PATCH/신고 본문도 확인했습니다.
- 운영 서버에 신청·응원·신고 테스트 데이터를 생성하지 않았으며 소셜 로그인 포함 실서버 전체 시나리오는 아직 실행하지 않았습니다. 모의 서버는 제품 코드에 포함하지 않습니다.
