# 분실물 게시판

- `/main#lost`는 `GET /api/v1/lost-items?size=50`의 공개 목록을 보여줍니다. 검색과 분실/습득 구분은 받은 최근 50건 안에서 적용합니다.
- 기존 게시판의 제목·내용 입력 화면을 유지합니다. 서버에는 둘을 줄바꿈으로 합친 최대 100자의 `description`, 장소, 선택한 발생 시각을 `POST /api/v1/lost-items`로 보냅니다. 기존 서버 글처럼 줄바꿈이 없는 설명은 제목으로 표시합니다. 작성한 글의 해결 처리와 삭제는 각각 `PATCH /lost-items/{id}/resolve`, `DELETE /lost-items/{id}`를 사용하며 서버가 작성자 권한을 검사합니다.
- 상세 API가 없어 `/main#lost/post/{id}`는 최근 50건 목록에서 해당 글을 찾습니다. 범위 밖이거나 비공개·삭제된 글은 표시할 수 없습니다.
- 사진은 글당 한 장이며 JPEG·PNG, 10MB 이하를 허용합니다. 선택 후 미리보기를 보여주고, 글 저장에 성공하면 `POST /api/v1/lost-items/{lostItemId}/images`에 multipart `file`로 업로드합니다. 사진만 실패하면 저장한 글 ID를 유지하여 사진만 재시도하거나 사진 없이 완료할 수 있습니다.
- 목록은 `image.thumbnailUrl`, 상세는 `image.imageUrl`을 표시합니다. 상세의 ‘내 글 사진 관리’에서 기존 글에 사진을 추가하거나 `DELETE /api/v1/lost-items/{lostItemId}/images/{imageId}`로 삭제할 수 있습니다. 교체는 기존 사진 삭제 후 등록합니다. `mine` 필드가 없으므로 로그인 사용자에게 관리 메뉴를 제공하고 실제 소유자 검사는 서버에 맡깁니다.
- 상세 하단에서 `GET /api/v1/lost-items/{lostItemId}/comments`로 댓글과 답글을 조회합니다. 비로그인도 읽을 수 있고, 등록은 로그인과 CSRF가 필요합니다. 댓글·답글 모두 1~200자이며 답글은 최상위 댓글에만 등록합니다.
- 서버의 댓글 `mine` 값으로 본인 댓글 삭제를, `postAuthor` 값으로 원글 작성자 표시를 처리합니다. 삭제된 댓글의 원문은 표시하지 않고 ‘삭제된 댓글입니다.’로 대체하며 남아 있는 답글을 유지합니다.
- 로그인한 사용자는 일반 분실물 글과 댓글·답글을 `POST /api/v1/content-reports`로 신고할 수 있습니다. 댓글 대상은 `LOST_ITEM_COMMENT`이며 사유는 20자 이내입니다.
- 운영자 화면에서는 공식 습득물 등록, 해결 처리, 공개/숨김, 신고 검토에 더해 댓글·답글 숨김/복구를 제공합니다. 댓글 신고 응답에 `lostItemId`가 없어 글 번호를 입력해야 합니다. 공개 분실물 목록의 ‘댓글 관리’로 진입하면 해당 글 번호를 자동으로 채웁니다.
- `GET /api/v1/auth/me`의 비로그인 401은 목록·사진·댓글 읽기 실패가 아닙니다. 이전 버전의 IndexedDB 글/사진/댓글은 서버 글로 이관되지 않습니다.

## 검증

- `npm run test:lost`: 기존 4개와 사진·댓글·답글·신고·운영자 댓글 공개 상태·입력 제한·오류 전파 검사 6개, 총 10개 통과.
- 로컬 모의 API로 사진 업로드 실패 후 재시도 시 글 중복 없음, 댓글·답글 등록/삭제/신고, 삭제 원문 숨김, 비로그인 조회, 운영자 댓글 숨김/복구를 브라우저에서 확인했습니다.
- 운영 서버에 테스트 글·사진·댓글·신고를 생성하지 않았습니다. 실제 계정과 이미지 저장소를 포함한 최종 확인은 배포 후 필요합니다.
